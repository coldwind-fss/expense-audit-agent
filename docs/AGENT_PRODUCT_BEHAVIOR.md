# Agent 产品行为

## 三个任务，一个执行基础

| 任务 | 触发 | 输入 | 输出 | 不能做什么 |
| --- | --- | --- | --- | --- |
| material_extract | 单份原件准备完成 | 授权材料页、材料类型与模式 | 角色、金额含义、日期、票号、购销方、候选及证据 | 不按文件名猜金额，不建行或分配 |
| line_suggest | 员工完成附件分配后请求 | 当前明细、已归属材料事实、字段来源 | 金额、日期、票种/费用类型建议 | 不写真实事由、项目、身份或独立总额 |
| claim_review | 员工请求整单审核 | 确定版本的申报、材料事实、公司、账户、关联与规则 | 检查、证据、下一步、是否满足本次提交 | 不跳过必要检查，不代员工最终提交 |

识别后即能查看单份金额，帮助员工人工归行；不需要等所有材料整理完才能得到第一份结果。回填复用可信事实和确定计算，足够明确时无需再次调用模型。

## 继续与停止

- **继续处理**：还有必要工具未执行，或允许范围内可补看证据。
- **完成**：任务产物完整。审核业务不符合也可以正常完成，结果为不可提交。
- **需要信息**：提出明确问题，进入waiting_input；不会无限等待模型猜测。
- **没有可用结果**：模型、结构、权限、预算或执行失败，明确结束，保留可用事实和恢复方向。

识别、建议和审核各自有任务状态，不能用“图已结束”替代“业务通过”。

## 人工权限

员工可以确认材料归属、选择建议、修改申报、补证、核对疑似重复，并在允许的付款角色范围确认实际金额。未付款订单不能靠人工金额变成成功支付；明确重复不能靠“不同”再次计入；手工付款金额不能认证税票或抬头。

管理员的受控修复和代发必须提供原因，并走同一完整规则。无通用放行开关，模型不能授予权限、更改主体、编造审批或自行发起OA。

## 建议采纳和撤回

建议显示原值、新值、证据和保护状态。人工/导入值需要明确替换确认；批次采纳原子执行，冲突不覆盖。撤回仅恢复该批次仍拥有的值，不覆盖后续人工修改。实际用途、项目与独立申报总金额保持人工输入。

## 输入变更后的处理

| 变更 | 行为 |
| --- | --- |
| 新原件或材料替换 | 准备/识别对应材料，再更新受影响事实和检查 |
| 归行或重复决定改变 | 更新计入，重新生成相关建议/审核 |
| 允许的付款人工金额改变 | 保存人工决定、提升修订，旧任务失效，基于最新输入建立任务 |
| 申报总额、行金额、公司、身份或关联改变 | 旧报告失效，提交前重新审核 |
| 纯阅读提示，业务内容未变 | 在同一任务/图线程受控恢复，不重置预算 |
| 旧Worker返回 | 因版本/租约失效而拒绝发布，不能覆盖当前事实 |

页面呈现材料事实、程序检查和可执行下一步，不展示模型隐藏推理。真实provider与fixture来源一直可见。
