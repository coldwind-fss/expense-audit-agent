# 产品基线

> 产品：循证 · 智能报销审核系统；版本：1.0；业务规则：reimbursement-v1-002。

## 1. 定位与目的

本产品是 OA 前置报销应用。员工在进入 OA 前填写真实申报并提供证据，系统完成材料理解、金额核验与业务审核，只有满足要求的申报才能进入对应提交路径。

业务来源于真实企业长期运行过的报销场景：费用入口增加、支付凭证格式多样、退款和多笔交易、票据混用、抬头和差旅范围等情况，使单纯 OCR 字段提取难以覆盖完整审核。

当前产品使用多模态模型与有界 Agent 处理材料语义，使用确定性规则约束财务与权限。项目交付完整应用流程及可运行源码，以合成企业数据和可替换外部适配器独立运行。

## 2. 产品边界

- 保留引导式表单、人工建行、真实事由和项目、人工附件分配、建议确认及最终提交。
- Agent 负责逐份材料理解、字段建议和整单审核组织；不自动创建、拆分或分配费用行。
- 员工独立填写申报总金额；该字段不由识别、明细合计、Excel 或 Agent 自动生成或覆盖。
- 进入基本信息即按报销归属人获取审批卡片，选择后关联；找不到时可按单号补查。当前外部读取由本地 Stub 提供。
- 不把“金额一致”等同于全部审核通过。身份、材料有效性、抬头、审批与日期仍需满足规则。
- OA、通知、目录及台账保持本地模拟；模型可用 fixture、disabled 或真实 provider。

## 3. 用户与主体

| 方式 | 操作人 | 报销归属人 | OA 发起人 |
| --- | --- | --- | --- |
| 本人 | 当前员工 | 当前员工 | 当前员工 |
| 普通代报 | 获准员工 | 所选员工 | 操作员工 |
| 管理员协助代发 | 管理员 | 案件员工 | 案件员工 |

归属部门、付款公司与收款账户独立表达。社保主体仅作为公司默认建议；税务发票抬头按实际选择的付款公司逐张核验。管理员修改他人申报需要处理原因，不能通过角色跳过金额或材料检查。

## 4. 业务入口

| 入口 | 材料与规则 | 下游去向 |
| --- | --- | --- |
| 日常有票 | 有效付款、有效发票、条件业务审批 | 日常报销 |
| 日常无票 | 有效付款；票种固定“无”，不混入发票附件 | 无票模板，保留后续人工审批 |
| 差旅 | 交通/住宿等明细，逐行出差审批与日期范围 | 差旅报销 |
| 项目 | 同项目多类费用，真实用途手填，不按关键词新增关联要求 | 日常报销 |
| 授权供应链 | 专属权限的发票路径，免付款但需税票与申报额匹配 | 日常报销 |

## 5. 五步工作台

1. **基本信息**：确认身份、归属、独立申报总金额、自动读取的审批、付款公司及收款账户。
2. **费用明细**：人工建立费用行，填写用途/项目/类型，必要时逐行关联出差审批；可暂缺等待材料的字段。
3. **上传与分配**：批量上传图片/PDF，逐份识别；预览事实、核对角色与疑似重复，再人工归行。
4. **识别回填**：生成日期、金额、票种和差旅类型建议；选择采纳，保护人工/导入值，支持受控撤回。
5. **审核与提交**：核对人工总额、明细和、付款/票据支持及其他规则，修正后重审，最后人工确认提交。

侧栏始终区分人工总额、明细合计与差额。新草稿总额为空；草稿允许未完成，最终提交必须具备正数人工总额。金额比较容差统一 0.01 元。

## 7. 关键状态与修正

草稿、Agent 任务、提交任务和模拟 OA 状态分别管理。识别完成不等于审核通过，审核通过不等于 OA 已创建，模拟创建不等于实际审批或付款。

修改申报总额、费用、材料、归属、公司等相关输入后，旧报告失效。用户修正后重新审核，不能用过期报告提交。后台任务返回时也必须核对输入版本和任务租约，不能覆盖新内容。

人工确认用于解决允许的付款金额或重复判断，不存在通用“强制通过”。缺审批状态、替票和借同行审批等未定义政策不由模型补造。

## 8. 验收要点

- 五入口及本人/代报/管理员路由可完整操作，身份不混用。
- 自动获取审批展示正确归属，切换归属后重新读取。
- 人工总额独立保存，识别和回填不覆盖；空、零、自动来源和超容差差额不得提交。
- 退款、优惠、未付款、佐证及重复凭证按角色计入，票据不足阻止。
- 逐张抬头、逐行差旅审批/日期、人工说明与 unknown 语义可见。
- 失败、预算或信息不足有明确结果，人工修改后旧报告不能提交。
- 重复提交、未知结果和旁路恢复不重复创建模拟 OA。
- 跨 workspace 拒绝访问，凭据和原件不由静态目录暴露。
